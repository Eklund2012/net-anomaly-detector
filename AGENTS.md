# Project guidance

- Use English for all communication, documentation, README files, and code comments.
- Treat this as an educational project: explain the purpose and new terms before each practical step.
- Give one practical step at a time and wait for the user's feedback or command output before continuing.
- Distinguish implemented behavior, empty placeholders, plans, and unverified assumptions. Claim success only with evidence.
- Explain and request approval before installing software, changing system configuration, creating VMs, or making major changes.
- Prefer simple, established tools and verify technical assumptions against official documentation.
- Use only synthetic subscriber credentials and isolated lab networks; never use real subscriber data or public test targets.
- Do not implement the ML pipeline until the user requests that stage.
